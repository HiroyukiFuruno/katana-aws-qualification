# #60 資格取得目標・学習予定

関連: [Issue #60](https://github.com/HiroyukiFuruno/katana-aws-qualification/issues/60)。ユーザーの最新指示により、#59の公開後、Facebookより優先する。#59はPR113で公開・Close済み。根拠となる現行調査は `test-results/site-preferences/milestones-design-audit.md`。

## 利用者のフロー

現状は学習・模試の実績をダッシュボードで振り返る。今回、そこから「次の資格取得目標を登録→学習・模試・本番試験の予定を登録→予定を確認して学習へ進む」までつなぐ。

| 対象 | 今回の到達点 |
| --- | --- |
| 取得目標 | 実在する資格IDと取得目標日を登録・編集・削除。複数資格を扱う |
| 予定 | 学習・模擬試験・本番試験の名称と日付、必要なら時刻を登録・編集・削除 |
| 確認 | 次の予定、取得目標日、残り期間を一覧と月カレンダーで表示 |
| ダッシュボード | 既存のウィジェット追加・表示・配置へ統合。配置と予定を別の正本にする |
| 学習へ戻る | 予定の資格から既存の学習・模試へ移動する |
| 実績との境界 | 日付経過で完了・受験・合格にしない。本番の取得記録は既存の本人による取得資格編集へ案内する |

## 最小の保存・画面境界

- 所有者は既存のAuth UID。本人限定RPCとRLSを使い、UIDをリクエスト引数にしない。別アカウント統合やCookie移行を前提にしない。
- 予定は専用の `certification_milestones` 一表に保存する。種別はtarget/study/mock_exam/exam、資格ID、名称、日付のみ又はUTC日時、本人が操作する完了フラグ、改訂を扱う。既存の学習イベント・模試結果・取得資格・dashboard_settingsへ予定そのものを埋め込まない。
- 取得目標は資格ごとに1件、学習・模試・本番の予定は同じ資格IDで関連付ける。目標日の削除で、その資格の予定を自動削除しないことを画面で説明する。
- 学習・模試・本番の完了は本人のチェック操作による自己申告とする。予定の完了は回答実績・模試得点・取得資格へ変換しない。targetに完了フラグを設けず、取得資格は既存の編集画面へ案内する。
- DBの行単位改訂で競合を拒否する。作成再送の重複、更新の結果不明、削除・取消し、所有者切替時の古い応答を実装前に契約化する。通信失敗を保存成功にしない。
- 学習リセットは予定を消さず、退会では本人の予定をcascade削除する。表示設定のリセットとも分ける。
- 会員の予定をクラウドへ保存して別端末で復元する。ゲストの学習・既存ダッシュボードを維持し、予定のための新しいゲスト保存や引継ぎは追加しない。
- 新規の既定配置とリセットには予定ウィジェットを含める。既存の保存済み配置を自動書換えせず、既存の追加操作から予定ウィジェットを選べるようにする。
- 種別は色に加えて文字ラベルを使い、カレンダーと同じ予定を一覧からも操作できる。スマホで横はみ出しを起こさず、キーボードで登録・編集・削除できる。
- 外部予約、課金、カレンダー同期、通知、別アカウントの統合は追加しない。

## 日付・時刻

- 取得目標日と終日予定は日付文字列として保存し、UTC変換で別日にしない。
- 時刻付き予定はUTCの瞬間として保存し、既存ダッシュボードのIANA timezoneで表示する。予定専用の表示timezone設定は増やさない。
- 時刻入力は端末のIANA timezoneを明示して行う。夏時間で存在しない時刻は、変換後の年月日時分の不一致を検出して拒否する。重複時刻はECMAScript Dateと同じ先の瞬間を採用する。表示はダッシュボードtimezoneであり、入力timezoneとの違いを明示する。固定入力と実browser contextのtimezoneで検査する。
- 残り日数・今日・過去の判定は表示timezoneの暦日を基準にする。経過したことを実施済みと扱わない。

## 保存契約

- 主キーは `(user_id, id)`、idは新規操作時に一度発行するUUID。同じ作成操作の再送では同じidを使う。削除後は同じ作成操作の遅延再送も拒否する。
- `list_certification_milestones(p_expected_generation)` は本人の配列を返す。各行は `id/certificationId/kind/title/plannedOn/plannedAt/completed/revision` の8項目だけ。
- `save_certification_milestone(p_id,p_certification_id,p_kind,p_title,p_planned_on,p_planned_at,p_completed,p_expected_revision,p_expected_generation)` は保存した行を返す。初回expected_revisionはnullでrevision0、更新は既存改訂とのCAS。同じpayload再送は改訂を増やさない。異なるpayloadの古い改訂はPT412、古い学習世代はPT409。
- `delete_certification_milestone(p_id,p_expected_revision,p_expected_generation)` は本人の行だけをCAS削除しtrueを返す。予定の6項目を消去し、同じ表にID・所有者・改訂・削除日時だけを残す。既に削除済みの再送はtrue、別の改訂が存在すればPT412。存在しないIDの削除も最小の削除記録を作り、作成との競合を同じ主キーで直列化する。
- 削除済み行はRLSとlistから除外し、saveはPT412で拒否する。削除記録も退会時にcascade削除する。別の所有者モデル、再送キュー、別の削除記録テーブルは作らない。
- 名称はtrim済み1〜120文字、資格IDは現行catalogのID、種別は上記4値、completedはboolean。targetは日付のみ・completed=false。予定は有効な日付又は時刻のどちらか一方。SQLとclientの検証を固定入力で照合する。
- 適用済み17件は変更せず、次は `202611220006_certification_milestones.sql`。dashboardの新kind/表示方式の許可は後続の追加migrationで行い、既存配置や改訂を上書きしない。
- 既存dashboard servicesへ本人用repositoryを接続する。予定読取・改訂・エラーは回答集計と分ける。新たな所有者・汎用同期モデルは作らない。
- 予定ウィジェットには資格の絞り込みとtimezoneだけを適用し、回答期間・カテゴリ・回答形式などの統計フィルターは適用しないことを表示する。月カレンダーと一覧を切り替えられるようにする。
