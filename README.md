# KatanA AWS

AWS認定13資格の学習・模擬試験・誤答復習とスキル査定のアプリ。ReactとTypeScriptで実装し、Viteで静的ファイルを生成する。アカウント認証にはSupabase Authを使用する。学習データは現在ブラウザ内に保存し、アカウント別のDB保存と分析は後続対応。

## 起動

Node.js 26とBun 1.4.5を使用する。`bun install --frozen-lockfile` で依存関係を導入し、`bun run dev` で起動する。`bun run check` はLint、フォーマット、翻訳キーとプレースホルダーの整合性、教材データの検証、模試のテスト、型チェック、静的ビルドを実行する。Vercel本番ビルドにも同じチェックが適用される。

トップページから「資格を選んで勉強する」と「スキルを査定する」に進める。英語は `/`、日本語は `/ja/`、ほかの言語は言語コードのプレフィックスに対応する。問題・選択肢・解説・査定問題の本文は日本語で提供する。ライトとダークの選択はブラウザ内に保存し、未選択の場合はOSの設定に従う。

画面文言は `src/locales/<言語コード>.json` で言語ごとに管理する。文言を追加する場合は `src/locales/ja.json` を基準に、ほかの言語へ同じキーとプレースホルダーを展開する。画面への文言の直書きは禁止し、本文・操作・入力補助・アクセシビリティ名を辞書から参照する。`bun run i18n:check` は再帰的な翻訳キー参照と辞書の整合性、`bun run i18n:hardcode` は画面に届く直書き文言を構文木で検査する。両方を通常の `check`、CI、本番ビルドで実行する。検査の範囲は [多言語UIの規約](docs/i18n.md) を参照。

TypeScriptとTSXは1ファイル150行までとし、Biomeで検査する。`bun run duplicates:check` はソースと開発スクリプトの重複や構造の近い関数を、`bun run architecture:check` は循環依存、解決できない参照、UIへの依存の向きを検査する。いずれも `bun run check` に含まれる。

## 問題の追加・改訂

問題データは `public/courses/<資格ID>/` のJSONに置く。対応するパスは `src/certifications.ts` で管理する。画面コードは問題数やカテゴリを固定していない。

- `id` は一意の設問ID。選択肢の `id` も設問内で一意にする。
- `correct` は正解の選択肢IDの配列。配列の長さが必要な選択数になる。
- 選択肢それぞれに技術的根拠を `explanation` として記載する。
- `version` は出典の版、`source` は出典リンクと画面上のラベル。
- 誤字の修正は `revision` を維持する。正解や出題意図を変えるときは増やす。回答回数と復習対象は設問IDと改訂番号の組み合わせで集計する。旧版の記録は全体の回答履歴とJSONLに残る。

執筆前に `bun run research:aws <AWS試験ガイドURL> [追加出典URL ...]` でAWSの一次資料を取得する。試験ガイド、同じガイドに含まれる分野・対象サービスのページ、ガイドからリンクされる試験案内を自動で収集する。必要なサービスドキュメントは追加出典に指定でき、次回も再確認する。移転・廃止された追加出典がある場合は、ガイドURLの直後に `--replace-supplements` を指定し、今後も追跡する追加出典を渡す。

出力は `test-results/aws-research/<ガイド名>/` に保存する。英語以外のガイドはディレクトリ名に言語を付ける。`latest.json` に本文の保存先、前回との変更、追加・削除があり、`runs/` に各回の記録が残る。公式の試験形式と分野を確認してから設問を作り、最後に正答の判断が重なる問題をレビューする。

## 保存と分析

GitHubによるSSOログインに対応する。初回SSOでアカウントを作成し、メール・パスワード登録は設けない。ログイン後はダッシュボードへ移動する（現在はアカウント設定と学習への導線）。設定がない環境でも、ログインせず学習できる。公開設定・秘密情報の保管・認証テスト・アカウント削除は [認証の設定と運用](docs/auth-setup.md) を参照。

`src/QuestionCard.tsx` が設問表示と回答操作、`src/questions.ts` がデータの読み込みと検証、`src/history.ts` が履歴の保存・集計・出力を担当する。

回答履歴はLocalStorageに保存し、誤答ID一覧は有効期限付きCookieへ保存する。Cookieが書き込めない場合や上限を超える場合は一覧もLocalStorageに保存する。保存先はブラウザプロファイルと配信元に依存する。

JSONLは1行1回答。回答日時はUTCのISO 8601、所要時間は設問の表示から採点操作までのミリ秒。回数は今回の回答を含み、過去の誤答回数は含まない。復習時の正誤は `reviewCorrect` に記録し、通常演習では `null` を記録する。リセットは確認後にアプリの保存データを削除し、削除を読み戻しで確認する。ダウンロード済みのファイルはブラウザのダウンロード先に残る。

## 模擬試験

開始時にショート、ミディアム、フル、カスタムから選べる。問題数と制限時間はプルダウンに表示する。ショートは最大15問、ミディアムは最大30問。カスタムは1問からフルの問題数まで指定でき、各形式の時間はフルの制限時間を問題数に応じて配分し、1分単位に切り上げる。

模試の拡充は資格単位でレビューして公開する。本試験と同じ長さへの拡充を公開する資格は、カタログで `reviewedMock` を設定する。教材データの検証で、その資格の分野別の出題枠それぞれに対して、類似グループを除いた候補が5倍以上あることを必須にする。

`public/courses/saa-c03/mock-questions.json` に模試の問題を置く。追加された問題は既存の問題と同様に、各分野の出題候補になる。学習モードでも、同じ問題を1問ずつ採点して学べる。模試は試験ガイドの分野比率に近い19問・17問・16問・13問で構成する。このアプリでは全65問を採点し、正答数を表示する。

模試では順序と途中回答を保存し、再読み込み後も同じ締切で続行する。時間切れを画面を開いている間、または再開時に検出して採点する。集計時は未選択や選択数が足りない設問も不正解として扱う。JSONLでは `mode: "exam"` と `examId` で模試結果を特定できる。模試の所要時間は、その設問を開いていた区間のうち、選択や画面内での移動時に保存できた時間と、提出までの最後の区間を含む。

設問をレビューした指摘と修正は [QUESTION_REVIEW.md](QUESTION_REVIEW.md) に記載する。選択肢や正解判定に関わる変更を配信する際は、進行中の模試を再開できるよう、旧版の配信データを残す。

解答後の「振り返り」は問題データの `learning` に記録する。`reason` に判断の決め手、`concept` にAWSの仕様や使い分け、`check` に条件を変えた確認問題とその考え方を書く。誤答時には実際に選んだ誤答と、選べなかった正答を、選択肢ごとの根拠とともに表示する。

## 資格と査定を追加する

資格の情報と教材の設定は `src/certifications.ts`、査定問題は `src/assessment.ts` に置く。新しい教材を公開する場合は `public/courses/<資格ID>/` に問題セットを置き、カタログに演習、模試、過去版のパスと制限時間・カテゴリ別出題数を登録する。問題IDは教材をまたいで一意にする。SAA-C03の既存問題IDと模試の保存キーは移行後も利用できる。

取得済み資格を除外し、未取得資格が必要とする分野だけを査定する。取得順は分野別の正答率・試験レベル・関連資格の学習順・近い試験終了予定を用いる。取得済みの設定と査定の回答はブラウザ内に保存される。学習のリセットは全資格の学習履歴と模試の記録を削除し、資格の取得状況と査定はロードマップ画面で更新する。

### Google サービスの本番設定

GA4 は KatanA 本家と同じ測定 ID を使い、サイトのプライバシー設定で同意した場合に読み込みます。Google Search Console で URL プレフィックスの HTML タグ認証を選んだ場合は、Vercel の Production に `VITE_GOOGLE_SITE_VERIFICATION` を設定してデプロイし、`/sitemap.xml` を送信します。

AdSense の確認用にアカウントのメタタグと `/ads.txt` を公開します。親ドメインが承認され、対象地域の同意メッセージが公開済みであることを確認した上で、Vercel の Production に `VITE_ADSENSE_SERVING=1` を設定すると、KAQ専用広告枠が有効になります。広告はCookie設定で「アクセス解析・広告を許可」を選んだ後に読み込みます。

トップ、学習一覧、資格ガイド、用語集では、画面幅1,520px以上のときに左右の余白へ広告枠を追加します。768px未満では本文の区切りに横長枠を1つ表示します。
