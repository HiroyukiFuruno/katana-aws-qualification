# 認証再開とアカウント獲得導線（#28・#29）

## 最新の指示・対象
- AndroidのGitHubアプリからブラウザへ戻ると、一般的な取消し/期限切れの画面が表示されたとの報告。
- アバターメニューだけでなく、新規登録の価値が伝わる導線をトップ・学習・模試結果・査定へ配置する。
- ゲストも保存同意後に端末履歴を分析可能にする（#23/#24）。アカウントの追加価値は複数端末同期と引継ぎ。未提供の同期/分析は準備中と明示する。

## 設計と検証条件
PKCEは維持する。開始情報が別の保存領域にある場合に秘密をURLへ渡して回避せず、現在のブラウザで新しいSSOを開始する。
verifier欠落はブラウザ切替だけでなく再読込でも生じるため、可能性として説明する。取消し、期限切れ、未知エラーを区別し、providerの生メッセージやcode/tokenを表示しない。
別browser contextの実Auth/OIDCで未使用codeの戻り、開始情報欠落、URL清掃、同じ戻りbrowserからの新flow成功を検証する。
code再利用は元のverifierを戻した上で実Authが拒否することを検査し、クライアント側の欠落拒否と混同しない。
