# KatanA AWS

AWS SAA-C03の演習・誤答復習用アプリ。ReactとTypeScriptで実装し、Viteで静的ファイルを生成する。サーバー側の学習データベースは不要。

## 起動

Node.js 22.13以降で `npm ci`、`npm run dev` を実行する。配布用には `npm run build` を実行し、生成された `dist/` をHTTP(S)で配信する。

## 問題の追加・改訂

問題データの編集先は `public/courses/saa-c03/questions.json`。配信時は `dist/courses/saa-c03/questions.json` としてそのまま配信される。画面コードは問題数やカテゴリを固定していない。

- `id` は一意の設問ID。選択肢の `id` も設問内で一意にする。
- `correct` は正解の選択肢IDの配列。配列の長さが必要な選択数になる。
- 選択肢それぞれに技術的根拠を `explanation` として記載する。
- `version` は出典の版、`source` は出典リンクと画面上のラベル。
- 誤字の修正は `revision` を維持する。正解や出題意図を変えるときは増やす。回答回数と復習対象は設問IDと改訂番号の組み合わせで集計する。旧版の記録は全体の回答履歴とJSONLに残る。

## 保存と分析

`src/QuestionCard.tsx` が設問表示と回答操作、`src/questions.ts` がデータの読み込みと検証、`src/history.ts` が履歴の保存・集計・出力を担当する。

回答履歴はLocalStorageに保存し、誤答ID一覧は有効期限付きCookieへ保存する。Cookieが書き込めない場合や上限を超える場合は一覧もLocalStorageに保存する。保存先はブラウザプロファイルと配信元に依存する。

JSONLは1行1回答。回答日時はUTCのISO 8601、所要時間は設問の表示から採点操作までのミリ秒。回数は今回の回答を含み、過去の誤答回数は含まない。復習時の正誤は `reviewCorrect` に記録し、通常演習では `null` を記録する。リセットは確認後にアプリの保存データを削除し、削除を読み戻しで確認する。ダウンロード済みのファイルはブラウザのダウンロード先に残る。

## 模擬試験

`public/courses/saa-c03/mock-questions.json` に模試の問題を置く。追加された問題は既存の問題と同様に、各分野の出題候補になる。学習モードでも、同じ問題を1問ずつ採点して学べる。模試は試験ガイドの分野比率に近い19問・17問・16問・13問で構成する。このアプリでは全65問を採点し、正答数を表示する。

模試では順序と途中回答を保存し、再読み込み後も同じ締切で続行する。時間切れを画面を開いている間、または再開時に検出して採点する。集計時は未選択や選択数が足りない設問も不正解として扱う。JSONLでは `mode: "exam"` と `examId` で模試結果を特定できる。模試の所要時間は、その設問を開いていた区間のうち、選択や画面内での移動時に保存できた時間と、提出までの最後の区間を含む。

設問をレビューした指摘と修正は [QUESTION_REVIEW.md](QUESTION_REVIEW.md) に記載する。選択肢や正解判定に関わる変更を配信する際は、進行中の模試を再開できるよう、旧版の配信データを残す。

解答後の「振り返り」は問題データの `learning` に記録する。`reason` に判断の決め手、`concept` にAWSの仕様や使い分け、`check` に条件を変えた確認問題とその考え方を書く。誤答時には実際に選んだ誤答と、選べなかった正答を、選択肢ごとの根拠とともに表示する。

## 資格と査定を追加する

資格の情報と教材の設定は `src/certifications.ts`、査定問題は `src/assessment.ts` に置く。新しい教材を公開する場合は `public/courses/<資格ID>/` に問題セットを置き、カタログに演習、模試、過去版のパスと制限時間・カテゴリ別出題数を登録する。問題IDは教材をまたいで一意にする。SAA-C03の既存問題IDと模試の保存キーは移行後も利用できる。

取得済み資格を除外し、未取得資格が必要とする分野だけを査定する。取得順は分野別の正答率・試験レベル・関連資格の学習順・近い試験終了予定を用いる。取得済みの設定と査定の回答はブラウザ内に保存される。学習のリセットは全資格の学習履歴と模試の記録を削除し、資格の取得状況と査定はロードマップ画面で更新する。

### Google サービスの本番設定

GA4 は KatanA 本家と同じ測定 ID を使い、サイトのプライバシー設定で同意した場合に読み込みます。Google Search Console で URL プレフィックスの HTML タグ認証を選んだ場合は、Vercel の Production に `VITE_GOOGLE_SITE_VERIFICATION` を設定してデプロイし、`/sitemap.xml` を送信します。

AdSense の確認用にアカウントのメタタグと `/ads.txt` を公開します。AdSense のサイト一覧でこの公開 URL の審査が完了し、プライバシーとメッセージで必要な地域の同意メッセージを公開し、自動広告を有効にした後、Vercel の Production に `VITE_ADSENSE_SERVING=1` を設定して再デプロイします。
