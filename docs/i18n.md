# 多言語UIの規約

画面文言は`src/locales/<locale>.json`へ置き、`usePreferences().t`から表示する。本文、見出し、ボタン、入力補助、エラー、アクセシビリティ名も対象とする。日本語だけでなく英語の直書きも禁止する。ブランドは固有名を維持して辞書で管理し、言語選択肢の自称は各辞書の`localeName`から読む。資格の正式英名は全辞書で同一に保つ固有名として管理し、カタログは共通の`messages.en.cert*Name`を参照する。この不変条件も辞書検査で照合する。

`bun run i18n:check`は10言語のキー・空値・プレースホルダーと、`src`配下の再帰的な翻訳キー参照を検査する。文字列のコード例やコメントを参照と誤認しないよう構文木を使う。

`bun run i18n:hardcode`は既存のSWCで全TS/TSXを解析する。表示先から追跡し、次を違反として終了コード1で報告する。

- JSX本文と表示属性、条件式・テンプレート・文字列連結。
- 追跡可能な定数、オブジェクト、配列、関数、コンポーネントのprops、stateを通じた直書き。
- 表示される生の`error.message`、ブラウザーのダイアログ、入力検証やDOMへの文言設定。

表示を伴わないURL・CSS・API識別値・診断文字列は、表示文言と区別する。任意の`translate="no"`やコメントで違反を無視する機能、既存違反のbaseline、ディレクトリ単位の免除は設けない。補間へ渡す固定の文言も辞書から参照する。

両検査は`bun run check`、CI、本番ビルドで実行する。検査の変更もCIの起動対象とし、正常例と違反例の単体回帰を維持する。翻訳を追加したら10言語の実画面・言語切替・小画面・アクセシビリティ名も確認する。

## 静的解析の限界

この検査は汎用の完全なデータフロー検証器ではない。ネットワークやJSONの本文、利用者の入力、Mapの更新などで実行時に組み立てたデータの全経路や翻訳品質を保証しない。UI用メタデータの型は`Message`へ限定し、実画面の回帰検査も組み合わせる。教材本文・用語定義などのデータは公開言語の契約に従い、UIの検査成功をデータ全体の翻訳完了と読み替えない。新しい表示経路を追加する際は、違反入力を検出できる回帰テストも追加する。

例えば`<button>Save</button>`や、定数へ移した`Save`の表示は禁止し、`<button>{t('save')}</button>`を使う。日本語を英語に直書きし直す、表示文言をpropsや補間へ移して検査を逃がす修正も行わない。
